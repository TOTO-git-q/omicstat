# Method basis — clusterprofiler-compare

Owner decisions are in `acceptance/exemplars/clusterprofiler-compare/PACK.md` S1 P-1 to P-3. Locked evidence: `L1_bioc3.23/clusterProfiler/Rd/compareCluster.Rd` for named lists and forwarded enrichGO arguments, plus `clusterprofiler-ora/L1_bioc3.23/clusterProfiler/Rd/enrichGO.Rd` for universe and ontology. GO uses registered org.Hs.eg.db 3.23.1 and GO.db in the locked container. Comparison dots show individual list enrichment profiles, not a statistical contrast between lists.

Testing families (S4; clusterProfiler 4.20.0 source read in the locked container): `compareCluster` calls the enrichment function once per list, so BH adjustment and q-values are always within a list. `enrichGO(ont = "ALL", pool = FALSE)` itself runs once per ontology, so each list x ontology has its own effective input, background and BH family; `pool = TRUE` makes the three ontologies one collection per list. The engine checks per family that denominators are unique and p.adjust equals BH over the family, and reports each family in `tables/test_families.csv`; it never uses a union of list backgrounds.

Anchors: (1) suite enforced-background preset test on an adapted fixture (gcSample lists intersected with DOSE geneList as explicit universe; independent direct compareCluster in the test); (2) replay of the original book example (`comparecluster-analysis.qmd` lines 31-42, commit 549613197f, sha256 in `acceptance/exemplars/clusterprofiler-compare/L2/manifest.tsv`) run verbatim on the unmodified gcSample lists and compared with the module run on the same lists with the implicit enrichGO default universe made explicit (all org.Hs.eg.db ENTREZID keys plus the gcSample IDs absent from OrgDb). The book source prints no values, so there is no printed anchor.
